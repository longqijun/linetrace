# log23 分析（bb_fast 档，跑 ~10 圈后进白区丢线停车）

> 背景：用**算法管理器里新建的 `bb_fast` 档（id=2, speed=17）**跑同一封闭跑道。PARAMS 里出现 `algoid=2 name=bb_fast` —— **确认算法管理单元已烧进去、在用**（id/name 都持久化并记进了 log）。
> 运行 ~103 秒（约 10 圈）后 LOST_STOP。

## 一、配置
```
algoid=2 name=bb_fast speed=17 algo=BANGBANG
turn_ratio=1.00 medium_ratio=0.65 sharp_ratio=-0.40 xsharp_ratio=-0.60
medspeed=0.90 shpspeed=1.00 hpspeed=1.00 minpwm=70 slew_rate=50000
```
和 log21/22 同一套"激进、弯道不降速"的参数，只是 **speed 16→17**（更快一点），且走的是 bb_fast 这个命名档。

## 二、统计：还是"刀尖上跑"，但 cross 修复见效
| 指标 | 值 |
|---|---|
| 数据行 | 1077 |
| 时长 | 103.0s（~10 圈） |
| **LOST(A/B) 占比** | **22.7%**（LOST_L=105, LOST_R=140） |
| CROSS(9) | **仅 5 次** |
| 档位 | STRAIGHT=187 MED=200 SHARP=252 HAIRPIN=147 |

两个要点：
1. **LOST 占比 22.7%**——和 log21/22（20~22.5%）一个水平，**没有稳定裕量**，每 4~5 个状态就有 1 个丢线，靠找线续命。能跑 10 圈还是靠运气（见 `log21-22分析.md`）。
2. **cross 修复确实生效**：整趟 CROSS 只触发 **5 次**（都是真横杠），不再像旧逻辑把居中的 CH4+CH5 误判成一堆 CROSS。说明"CH7/8 且 CH1/2 才算 cross"改对了。

## 三、翻车经过（NR 1078–1095，解码）
前面 ~10 圈基本靠"短暂丢线→快速找回"撑着（全程只有 3 处 dt≥600ms，且都在最后这段）。终局是一次收不回来的连环：
```
...LOST_R/LOST_L 反复挣扎...
E465 08 0 57 108   STRAIGHT   短暂回中(465ms)
E4  0C 4 97 63     MEDIUM_R   线到右
E2  0F 8 108 -37   HAIRPIN_R  线冲到最右(CH1-4)
E20 5F 9 108 36    CROSS      pattern 5F=很多路白
H500 FF 9 108 108  全白!      8路全白, 直行穿过
H500 FF 9 108 108  全白!      持续~1秒
E1394 0F 8 108 8   HAIRPIN_R  1.4s后线又出现在最右
E28 06 6 108 -43   SHARP_R
E2  04 4 97 57     MEDIUM_R
E10 00 B 108 -37   LOST_R     线又丢到右边
H500 00 B ...      原地反转找线(内轮-37/-43)
E1501 00 C 0 0     LOST_STOP  找了1500ms没找回 → 超时停车
```
**关键**：跑到某处冲进一大片**全白区(FF)约 1~1.4 秒**（可能是起点/终点白横杠区，或车冲出到白面），期间只能盲目直行；之后线短暂再现又立刻丢到右边，**盲目找线(原地右转反转)找了满 1500ms 没找回 → 触发 LOST_STOP**。

与 log22（左发卡甩飞）不同，log23 是**右侧丢线 + 进白区 + 找线超时**——翻车的**位置和形式随机**，再次印证"哪个弯翻、怎么翻是运气"。

## 四、结论与建议（与前几趟一致，再加两点）
1. **没裕量**：22.7% 丢线率 = 常年在崩溃边缘，10 圈是运气。`shpspeed=hpspeed=1.00`（弯道零降速）+ `turn_ratio=1.00`（外轮不降速）+ speed 提到 17，全是"冲"，必然高丢线。→ **弯道降速**（shpspeed/hpspeed 降到 0.6~0.7）把 LOST 占比压到个位数才算稳。
2. **盲目找线是终结者**：终局那次 1500ms 原地反转没找回就是致命一击。找线策略值得改（别盲目大幅反转赌方向，见 `log20分析.md`）。
3. **进白区(FF)约1.4秒**：说明车会冲进大白面/横杠区并盲走一段。若这是起终点横杠，可考虑对"整片全白"单独处理（保持上一次转向/短暂直行有上限），别让它盲走太久后从奇怪角度重新找线。
4. 附带确认：**cross 修复有效**（CROSS 仅 5 次），**算法管理器可用**（bb_fast 档生效并记进 PARAMS）。

判据不变：盯 **LOST 占比**，压到个位数才叫"稳定能跑完"。
