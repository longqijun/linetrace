# log4.txt 分析报告

**分析基于的代码版本（commit）**：`9db3f99cccb1abda65a39092d3573f8f4dc1d76a`
（fix: log dump大文件时yield()避免触发任务看门狗复位，2026-07-22）

背景：log4.txt 是一次 `track on`→`track off` 的实测记录（BT print on），算法切换为
`TRACK_ALGO_PID`（track_module.cpp:162-182），测试时长约 15.75s
（1721451ms ~ 1737202ms，共 526 条 `T` 调试记录）。

当前 PID 参数为默认值（track_module.cpp:26-28）：**Kp=40, Ki=0, Kd=5**，
base=102（对应 config_get_speed() 的低速档）。

## 1. 比例项工作正常，但增益明显偏小

稳态数据与纯比例公式 `output = 40 × error` 完全吻合：

| E | 输出 | L/R |
|---|---|---|
| ±0.25 | ±10 | 92/112 |
| ±0.50 | ±20 | 82/122 |
| ±0.75 | ±30 | 72/132 |
| ±1.00 | ±40 | 62/142 |

问题：误差打满时修正量只有 ±40，仅占 base(102) 的 ~39%、占 PWM 满量程(255) 的
~16%，转向权威明显不足，弯道容易跟不上。

## 2. 丢线极其频繁——本次PID表现的核心症状

按 mode 统计 526 条记录：

- PID: 336 条 (63.9%)
- CROSS: 32 条 (6.1%)
- **LOST_R/LOST_L: 158 条 (30%)**，共 6 段独立丢线事件，每段持续约
  800~1300ms（接近但未超过 1500ms 的 LOST_TIMEOUT_MS，没有真正触发停车）

规律很一致：每次误差被顶满到 E=±1.00 之后（例如 track_module.cpp 对应日志
`...E:+1.00` 下一帧直接变成 `LOST_R`），车辆几乎立刻丢线——说明车速相对弯道
曲率而言，PID 给出的差速修正跟不上，车直接冲出赛道，随后靠丢线后"延续上次
方向"的固定量（±40 左右，同样很弱）盲找，占了近三分之一的巡线时间在盲找线
而非真正闭环控制中。

## 3. 微分项在放大噪声，出现满幅打摆

日志中出现 4 次瞬时 `L:-255 R:255`（或反向）的满幅尖峰。根因是
`sensor_position_from()`（sensor_module.cpp:40-50）只输出 9 档离散阶梯值
（-1.00~+1.00，步进 0.25），微分项对着一个阶梯信号求导，一旦传感器噪声导致
误差瞬间跳档，`derivative` 会被放大到远超实际趋势的量级，Kd=5 把它进一步放大
到饱和。这种瞬间正反打满会让车身猛烈甩动，很可能是丢线的直接诱因之一。

## 4. 结论

本质上现在是"披着 PID 外壳的弱 P 控制器"：Ki=0 没有积分作用；Kd=5 对离散量化
误差是弊大于利，只在噪声/阶跃时贡献了几次危险的满幅抖动；真正起作用的比例
增益又明显偏弱，导致约 30% 的时间处于丢线状态。**当前PID调参效果不理想。**

## 5. 调参建议

1. 大幅提高 Kp（比如到 100+），让打满误差时修正量占满量程更大比例，提升急弯
   跟随能力；
2. Kd 建议先置 0 或大幅调小，并且改成对"测量值"求导而非对"误差"求导（避免
   阶跃冲击），或加一阶低通滤波再微分；
3. 更根本的改进：原始 ADC 值其实是连续量（日志里能看到原始打印的模拟值），
   可以用加权模拟量代替现在 5 路二值判断的离散 position，这样微分项才有意义、
   噪声也会小很多。
