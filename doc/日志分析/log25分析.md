# log25 分析（loop 卡顿修复后首测：卡顿消失 + 98s 无撞停）

> 背景：烧入 c490974（去掉 `out()` 的持续 flash 写、修 loop 周期性卡顿）后，用 `lograte=10` 抓的 log。
> 配置：bb_fast 档，speed=17，`lograte=10`，同 log24。

## 一、✅ loop 周期性卡顿：已消失
| 指标 | log24（修复前） | **log25（修复后）** |
|---|---|---|
| H 心跳总数 | 5888 | 9138 |
| H 间隔 = 10~11ms | 绝大多数 | **全部（10ms×8975 + 11ms×163 = 9138，100%）** |
| **H 间隔 ≥40ms（卡顿）** | ~36 次，最大 **211ms** | **0 次** |

**每一条心跳都是 10~11ms，连 12~39ms 的都没有** → **控制回路现在真正每 ~1ms 连续跑，不再有 50~211ms 的盲跑**。去掉 `out()` 里的 flash 写（问题 01）**确认有效**。

## 二、跑得更久：98 秒内 0 次撞停
- TRACK_OFF：`elapsed=150293ms  duration=98381ms  lines=10410`。
- **缓冲在 ~98 秒（10410 行）写满就停了**，车实际跑到 150 秒；log 只覆盖前 98s。
- 已记录的 98s 里 **一次 `LOST_STOP(00 C)` 都没有**，结尾是正常直行（缓冲满截断，不是撞停）。
- 对比：log24 68s 撞停、log22 48s 撞停。**这趟前 98s 全程跟住线没停。**

**可能是修复的功劳**：卡顿期间控制回路冻结、车盲跑几十~两百毫秒，很容易把一次"擦边"变成"甩飞"；现在连续控制，near-loss 都能及时救回来。不过也不能排除有 run-to-run 运气成分（见 `log21-22分析.md`：系统仍是临界稳定），需多跑几趟看是否稳定复现。

## 三、仍然 marginal
- **LOST 占比 19.0%**——还是"每 5 个状态就有 1 个丢线"，靠找线续命。只是现在每次都救回来了（98s 内），没演变成撞停。
- cross 收紧继续有效：整趟 **CROSS 仅 3 次**（真横杠），居中读数不再误判。

## 四、次要：10ms 下缓冲只够 ~98s
本趟证实：`lograte=10` 时缓冲约 **98 秒 / 1 万行**写满（约 215KB）。要录完整的 150s 一趟，可临时 `lograte 15` 或 `20`（换更长时间、稍疏一点）；抓瞬态才用更小值。

## 五、结论
1. **loop 卡顿修复确认有效**：10ms 采样全程 10~11ms、零大间隔。控制回路不再周期性盲跑。
2. 顺带这趟跑得更久（前 98s 无撞停，实际 150s），值得再跑几趟确认是不是稳定改善、还是运气。
3. 仍是激进参数、LOST 19% 没裕量——下一步给系统裕量（弯道降速把 LOST 压到个位数），才能从"每次都惊险救回"变成"稳当不丢"。
