# log14 数据分析报告（新算法：中心直行+三档）

> 背景：应用"中心两路直行 + 对称三档"改动后新抓取。跑直线，仍有点漂，**跑着跑着往外扭得很厉害**，但比 log13 好一点。
> 参数：speed=17 base≈108, medium_ratio=0.35, sharp_ratio=-0.40, xsharp_ratio=-0.60, slew_rate=600。

## 一、改动确认有效：起步 ~1.3 秒真·直行

log13 里从头到尾一次都没进 STRAIGHT，居中读数被判成转向。log14 开头完全不一样：

| 行号 | pattern | 模式 | L/R |
|---|---|---|---|
| 18/20/22… | `08`(CH4) / `10`(CH5) | **0 STRAIGHT** | 108/108 |
| 17/19/21… | `18`(CH4+CH5) | 9 CROSS(直行穿过) | 108/108 |

前 ~1.3 秒（行 17–44）小车稳定在中心两路，**左右轮都是满速 108/108，笔直向前**。这正是我们要的效果——中心死区吸收了小抖动，不再像 log13 那样一上来就摆。**用户观感"好一点"就来自这段。**

> 注：`18`（CH4+CH5）仍被判成 mode 9 CROSS，因为 CH5=index4 属左半、CH4=index3 属右半，触发了"左右两半同时压线=十字"判定。但 CROSS 也是直行 108/108，功能上没问题，只是标签是 9 不是 0。可后续优化（见建议 4）。

## 二、剩余问题：漂出去 → 丢线 → 猛回舵 → 冲过头 → 大幅左右摆的极限环

~1.3 秒后线漂到 CH6（行 45），从此进入**持续大幅左右摆动**，一直摆到彻底丢线停车（行 185 LOST_STOP），总共撑了 19.4 秒（log13 只有 10 秒）。典型一个来回：

```
中心直行 → 线漂到CH6/CH7(左) → 修正没跟上 → 线溜出左边缘 LOST_L(A)
   → 内轮猛反转找线 → 冲过头，线甩到右边 CH3/CH2/CH1 → 右侧急转/发卡反转
   → 又冲过头 LOST_R(B) → 再甩回左边 …… 循环
```

L/R 反复出现 `-43 / -63 / -64` 这种深度反转值，就是"往外扭得很厉害"的来源。

## 三、根因（三个叠加，附数据佐证）

### 1. slew_rate=600 太慢，小修正来不及生效，线就溜走了
mode 3（CH6）目标内轮 = base×0.35 ≈ **37**，但看实际下发：

| 行 | 模式 | pwm_l 实际 | 说明 |
|---|---|---|---|
| 45 | 3 | 107 | 刚进档，几乎没降 |
| 46 | 5 | 98 | |
| 47 | 3 | 91 | 26ms 只从 108 降到 91 |

600/s = 0.6/ms，从 108 降到目标 37 需要约 **118ms**。可线在 CH6/CH7 边缘只停留几十毫秒就溜出去丢线（行 48 LOST）。**内轮还卡在 ~100 没真正减速，车几乎还在直行，线就跑没了。** slew 把有用的小修正压得死死的。

### 2. 丢线后按 sharp 反转猛掰去找线，线其实只差一点点 → 冲过头
丢线分支里 `_last_dir<0` 时 `pwm_l = sharp_turn = base×(-0.4) ≈ -43`（内轮深度反转原地掰）。但线只是刚溜出边缘一点点，这一猛掰直接把车头甩过中心到另一侧。更糟的是 slew 让这个反转值退不回来：

- 行 48/49：LOST，pwm_l 冲到 **-42**
- 行 49：pattern `10`(CH5) 已经**找回线、模式变 0 STRAIGHT**，但 pwm_l **还是 -42**（slew 还没爬回来）→ 车继续朝左猛掰 → 冲过中心 → 行 52 起线甩到右侧 CH4/CH3…

**"找回线了却还在猛掰"** 就是过冲的直接机制：violent 的找线反转 + slew 慢恢复，联手把车推过头。

### 3. sharp/xsharp 负比例（-0.4/-0.6）本身太激进
边缘一旦触发（CH7/CH8/CH2/CH1），内轮直接深度反转，配合上面两条，每次都过冲，最终形成稳定的大振幅极限环——不是逐渐发散，而是**持续满幅左右横扫**，直到某次彻底丢线停车。

> 另：第一次漂是往左（线→CH6），可能有轻微机械/电机左偏，但很快被左右振荡淹没，属次要因素。

## 四、建议（按优先级）

1. **降低"找线/边缘反转"的激进度（最直接治"往外扭"）**
   - 丢线找线别用 `sharp_turn` 深度反转，改用 `medium_turn`（不反转，内轮 ~37）或延续上一档的力度，减少过冲。这条在 `track_update()` 丢线分支里改。
   - `sharpratio` 从 -0.40 调到接近 0（如 0~+0.2）、`xsharpratio` 从 -0.60 调到 -0.20 左右，先把反转幅度收下来（运行时命令即可，先试）。

2. **提高 slew_rate**，让小修正跟得上漂移、让过冲后的恢复更快。先试 1200~2000，甚至临时不限速对比。当前 600 对"小修正"伤害大于对"猛反转"的抑制。

3. **治本：中心死区太宽，漂移在直行区累积没人管，冲到 CH6 才第一次修正，已经晚了。** 两条路选一：
   - 给 CH5/CH4 单独压线时补一点**很轻**的比例修正（会重新引入一点中心微抖，需权衡）；或
   - 直线段直接上 **PID**（kp=40/kd=5 已配好）。PID 连续按偏差修正、没有死区、没有档位硬跳变，是从根上消除这种极限环最干净的做法，建议认真实车试一次。

4. **降速**：speed 17（base≈108）对当前 slew/几何偏快，修正来不及。先降到 12~14 留出裕量再调其它参数。

5. （小优化）把 `18`(CH4+CH5) 从 CROSS 判定里排除，让它归为 STRAIGHT(0)，日志更直观；真正的十字应要求更多路同时压线。

## 五、结论

改动**方向正确、确有改善**：起步 1.3 秒实现了真直行，总时长也从 10s 拉到 19s。剩下的"往外扭"不是中心判定的问题了，而是**边缘修正的动力学问题**：小修正被 slew 压得跟不上漂移 → 丢线 → 猛反转找线冲过头 → 大幅左右极限环。优先改"找线别猛反转 + 提高 slew"，治本考虑直线段用 PID。
