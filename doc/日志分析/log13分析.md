# log13 数据分析报告

> 数据背景：传感器校准后新抓取的数据，跑的是**直线**。一开始还好，最后偏出去了，约 3 秒的有效数据。

## 一、数据解码（关键点）

传感器位号：**CH8=最左 … CH1=最右**，中心在 CH4/CH5 之间。patHex 里置 1 的位 = 压在线上的传感器。以「左为正」记录线相对小车的位置，整段轨迹如下：

| 时间段(约) | 行号 | 线的位置(左+) | 模式 | 左/右PWM | 说明 |
|---|---|---|---|---|---|
| 0–2.9s | 15–30 | 0 ~ +0.5 | 反复在 CROSS/LEFT/RIGHT 之间跳 | 中心附近 | **看似还好**，但一直在小抖 |
| ~3.0s | 31 | — | **LOST_L** | 74/108 | 第一次丢线 |
| 3.0–4.5s | 32–46 | +1.5 ~ +2.5 | MEDIUM_L→SHARP_L→**HAIRPIN_L** | 左轮压到 55→35→17→**5** | 车偏到线右侧，猛向左掰 |
| ~4.6s | 47 | — | LOST_L | | 又丢 |
| 4.6–5.0s | 48–50 | 0 | 短暂回中 | | 回来一下 |
| 5.0–5.6s | 51–53 | −1 ~ −2 | MEDIUM_R→**SHARP_R** | 右轮 74→36→**−42(反转)** | 冲过头到线左侧，猛向右掰 |
| 5.6–6.2s | 55–61 | +1 ~ +3 | MEDIUM_L→SHARP_L→**HAIRPIN_L** | 左轮 79→46→**−64(反转)** | 又冲回左边 |
| 6.2s→ | 62–65 | — | LOST_L → **LOST_STOP** | 0/0 | 彻底丢线停车 |

## 二、核心问题

**1. 整段跑直线，从头到尾一次都没进 STRAIGHT(0) 模式。**
这是最关键的证据。跑直线本该绝大部分时间是 mode 0，但日志里 mode 0 一次都没出现。

**2. 居中状态被误判成"十字路口(CROSS)"。**
凡是 patHex=`18`（CH4+CH5 两个中心传感器同时压线，也就是最标准的"正对着线"）都被判成了 **mode 9 = CROSS**；只压 CH5 判 LEFT，只压 CH4 判 RIGHT。也就是说**小车根本没有一个"稳定直行"的状态**——最理想的居中读数反而触发了岔路逻辑，输出还在 L76/R108 和 L108/R76 之间来回翻，一开始就在小幅摆动。

**3. 小摆动被 BANGBANG 分档 + 内轮反转放大成发散振荡。**
参数 `sharp_ratio=-0.40 xsharp_ratio=-0.60` 意味着 SHARP/HAIRPIN 档会让内侧轮**反转**。跑直线时一旦偏一点，档位一路窜到 SHARP/HAIRPIN，内轮反转 → 原地猛掰 → 冲过头到另一侧 → 再猛掰回来。看 PWM：左轮 5、右轮 −42、左轮 −64……**摆幅越来越大**，是典型的不稳定（发散）控制，最后把线甩出传感器阵列之外，LOST → STOP。

**结论**："一开始还好、最后偏出去"的本质**不是机械跑偏，是控制器在直线上自激振荡，越摆越大直到丢线。**

## 三、建议（按优先级）

1. **修模式分类**：`18`（相邻中心两路）以及单中心应判为 **STRAIGHT**，左右轮给相等高 PWM。真正的 CROSS 应要求很多路同时白（比如 ≥4~5 路或一大块），别用两路中心去触发。这一条大概率直接解决问题。
2. **直线段改用 PID**：参数里 `pid_kp=40 pid_kd=5` 已经配好了，BANGBANG 这种离散分档对直线天生爱振荡。用 PID 连续控制会平滑很多；`ki=0` 可以先保持。
3. **收敛激进度**：跑直线不该窜到 SHARP/HAIRPIN。要么把各档的进入阈值放宽（`turn_ratio/medium_ratio` 对应的分界），要么把负 ratio（内轮反转）只留给真正的急弯，避免直线上出现反转。
