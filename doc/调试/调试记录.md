# 巡线调试记录

## 2026-08-09

### 今日进展

**1. log13 分析：定位到 BANGBANG 老算法的核心缺陷**
- 跑直线时从头到尾**一次都没进 STRAIGHT 模式**，最理想的居中读数（CH4+CH5 两路压线）反被判成 CROSS，单中心被判成 mild 转向。
- 结果：小车没有稳定直行状态，一上来就小幅摆动，被 sharp/xsharp 的内轮反转放大成发散振荡，约 3 秒就甩出线丢失停车。
- 详见 `log分析/log13分析.md`。

**2. 修改 BANGBANG 算法：中心直行 + 对称三档**
- CH4/CH5（一路或两路）→ **直行**，左右轮满速，不做修正。
- 去掉最内层 mild 档；转向按对称三档：CH3/CH6 一档（medium 不反转）< CH2/CH7 二档（sharp 反转）< CH1/CH8 三档（xsharp 反转）。
- 改动文件：`track_module.cpp`（删 mild 定义/布尔量/两个分支）、`track_module.h`、`print_module.cpp`（legend）。
- 方案文档 `BANGBANG算法修改方案.md`。

**3. log14 分析：改动方向正确，确有改善，但仍漂**
- 起步 **~1.3 秒实现真直行**（mode 0/9，108/108），总时长从 10s 拉到 19s。用户观感"好一点"。
- 剩余问题：跑着跑着漂到边缘 → 修正跟不上丢线 → 按 sharp 反转猛掰找线冲过头 → 大幅左右摆动的极限环，"往外扭得很厉害"。
- 三个叠加根因：① slew_rate=600 太慢，小修正来不及生效；② 丢线找线用 sharp 深度反转（-43）过冲，且 slew 让反转退不回来（找回线了还在猛掰）；③ sharp/xsharp 负比例（-0.4/-0.6）本身太激进。
- 详见 `log分析/log14分析.md`。

### 下一步调试方向

**方向 1：按 log14 结论做参数/逻辑调整（软件侧）**
- [ ] 丢线找线不再用 `sharp_turn` 深度反转，改用 `medium_turn`（不反转）或延续上一档，减少过冲。（改 `track_update()` 丢线分支）
- [ ] `sharpratio` -0.40 → 往 0 收（试 0 ~ +0.2）；`xsharpratio` -0.60 → -0.20 左右。（运行时命令先试，不改默认）
- [ ] 提高 `slew_rate` 600 → 试 1200~2000，甚至临时不限速对比，让小修正跟得上漂移、过冲后恢复更快。
- [ ] 降速 speed 17 → 12~14，留出修正裕量再回调其它参数。
- [ ] （治本，可选）直线段试 PID（kp=40/kd=5 已配好），连续修正无死区，从根上消除极限环。
- 建议顺序：先"找线不猛反转 + 提高 slew"两条组合，最直接压"往外扭"；再逐项加。

**方向 2：确认轮子的传动比（硬件/标定侧）**
- 目的：log14 第一次漂总是先往左（线→CH6），怀疑左右轮存在系统性偏差——若同 PWM 下左右轮实际转速/线速度不等，直行就会天然跑偏，再好的算法也是在补偿这个偏差。
- [ ] 测量/核对左右电机+减速箱的传动比、轮径是否一致。
- [ ] 同一 PWM 下分别实测左右轮转速（或让车原地/直线跑固定时间量偏移量），确认是否需要在代码里给某侧加补偿系数。
- [ ] 若确有固定偏差，考虑在 `motor_set`/base 下发处加左右平衡补偿，把"直行"先做正，再谈转向修正。

## 2026-08-09（续）：直线攻克 + 弯道起步

### 进展
**1. log14/15：slew 是"往外扭"主因**
- log14（改中心直行三档后）起步 1.3s 直行，但仍漂出去；三根因：slew=600 软件延迟、丢线用 sharp 反转找线过冲、sharp/xsharp 太激进。
- log15：`slewrate 5000` + 软化 ratio 后**直线不再丢**，3s 干净直行 + 有界小蛇形。**证明主因是软件延迟(slew=600)约 200ms 执行滞后，机械延迟不是瓶颈**（详见 `log分析/log15分析.md` 第八节）。

**2. log16：PID 直线笔直**
- `algo 1` 切 PID（kp40/ki0/kd5, slew5000）：直线 err 全程 ±0.33 内、PWM 108±15、无反转无摆——**直线达标**。详见 `log分析/log16分析.md`。

**3. 机械延迟 / 硬件线索**（`如何判断当前有没有机械延迟.md`）
- 用户对比：自己减速箱慢一拍，别人直驱快。结论：减速箱确实慢（反射惯量∝比²、backlash），但**直线非瓶颈**（log16 已证），高速/急弯才吃亏。
- 齿轮比：现 114.7:1，可选 38.2:1 / 12.7:1。当年 38.2:1"冲出去"是 5 传感器+bang-bang+软件延迟的锅，非齿轮。**建议先回 38.2:1 重测**，再考虑 12.7:1；换比要同步降 speed、重调 PID。
- 电机选型汇总见 `电机选型_空心杯无刷.md`（中/日品牌+链接）。

**4. log17：弯道（bang-bang）每弯必险，跑几圈后冲出**
- 用 bang-bang 跑弯道 64s/若干圈，但每个急弯都"丢线→大幅反转找线→勉强找回"（LOST 50+ 次），最后一次找线赌错方向冲出赛道。
- 根因：**恒速冲进弯，来不及转就冲到最外侧丢线**。详见 `log分析/log17分析.md`。

**5. 实现"方案A：弯道分档降速"（bang-bang，已改代码）**
- 逻辑：bang-bang 各转向档按"前进速度系数"整档降速，弯越急越慢，进弯前先收速。**只改 bang-bang，PID 与丢线找线完全不动，两套分开。**
- 新增运行时命令（百分比 0~100）：
  - `mediumspeed N`（MEDIUM CH3/CH6，默认 85）
  - `sharpspeed N`（SHARP CH2/CH7，默认 65）
  - `hairpinspeed N`（HAIRPIN CH1/CH8，默认 50）
- `save` 持久化；PARAMS 日志新增 `medspeed/shpspeed/hpspeed/minpwm`；`LOG_LINE_MAX` 320→384。
- 涉及文件：`track_module.cpp/.h`、`config_module.cpp`、`cmd_module.cpp`、`print_module.h`。
- **状态：代码已改，未编译/未实车验证**（本机无 arduino-cli/pio）。

**6. 关键约束：电机死区大 → 方案A降速空间有限（已加防堵转保护）**
- 实测**车速不能小于 speed 16（PWM<~102 起步转不动）**，静摩擦死区很大。
- 加了 `minpwm`（默认 70=日志里外轮实测能持续转的值）：外轮降速后不低于此地板，防弯道堵转停车；`minpwm N` 可调。
- sharp/发卡的**内轮反转保持满速 base**，不被降速削弱（否则发卡转不过来）。
- 代价：外轮本就被 turn_outer_ratio 压到 ~70(接近死区)，speed=17 下 sharp/发卡外轮被 minpwm 抬回 70=旧值，**只有 MEDIUM 档(91)真降下来**。"太快冲进弯"根子在死区/齿轮比(硬件)，软件能做的有限。详见 `log分析/log17分析.md` 方案A小节。

## 2026-08-09（续2）：弯道 log18/19/20 —— 软件方案A到顶，重心转硬件/找线/前探

### 进展
**7. log18（方案A第一版，均0.85，无minpwm）**：仍在发卡弯 thrash-off 冲出，和 log17 同坑。且第一版把发卡内轮也削弱了(-54 vs -64)。→ 促成加 minpwm 的第二版。详见 `log分析/log18分析.md`。

**8. log19（第二版：minpwm=70+满速内轮，均0.85）**：代码按设计正确工作（外轮floor到70、内轮恢复-64），但**结局没变**，仍发卡冲出。对比发现：全0.85+minpwm70 下 sharp/发卡外轮被地板顶回 70=原始值，**方案A只改了 MEDIUM(91)，动不了 sharp/发卡**。详见 `log分析/log19分析.md`。

**9. log20（sharpspeed=70）**：跑最久 67s，但**sharpspeed 70 被 minpwm 完全吃掉、和 0.85 输出一模一样**（外轮都floor到70）——67s 是"退回原始行为+运气"，不是参数功劳。发卡处反复上千毫秒盲目反转找线（行807 dt=1011ms 险停），最后没救回来。详见 `log分析/log20分析.md`。

**10. 结论（log17/18/19/20 四次坐实）**：**在 speed=17 下，软件方案A 动不了 sharp/发卡**（被 minpwm 地板顶死），`sharpspeed/hairpinspeed` 调了等于没调。发卡失败是"车速降不下来"的**硬件墙**，不是软件参数问题。

**11. 传感器前探设计**（`传感器前探设计.md`）：回应"前探后弯道数据更乱/像冲出去"的疑问——前探读数是"弯道预告"不是"当前位置"；线出视野=前探过长；解法=前探配最紧弯 或 双排(贴轮子一排管真实位置+前方一排管预判)。

**12. 观察**：log20 里**左发卡(LOST_L)明显更难缠**，长 thrash 多在左侧，疑轻微左偏（与早期"总偏左"一致），待确认左右对称性。
