## 问题：切换 algo 时参数不按算法记忆，每次切换都要重设

- **提出时间**：2026-08-09 17:41
- **解决时间**：2026-08-09 17:48
- **状态**：已解决（代码已改，待编译/实车验证）

**用户反馈**：algo 0(bangbang) 和 algo 1(pid) 有很多参数是共用的（比如速度 speed），每次切换 algo 时，之前那套参数都要全部重新改一遍，很麻烦。

### 诊断
- 各算法**独有**的增益本就不冲突：bangbang 只读 `turn/medium/sharp/xsharp_ratio`、`medspeed/shpspeed/hpspeed`、`minpwm`；pid 只读 `kp/ki/kd`。切 algo 时它们互不覆盖、都还在。
- 真正"共用但想要不同值"的是 **`speed` 和 `slew_rate`**（两个算法都用、最优值不同）。老实现把所有参数拍平存一份，所以换算法后想跑好就得手动重设 speed/slew（以及分不清哪套增益属于哪个算法）。

### 解决方案：每算法独立"参数档案"（用户选定"完整档案"方案）
- 新增 `AlgoProfile` 结构，`bangbang` 与 `pid` **各存一套**：`speed + slew_rate + 该算法全部增益`。
- **切换 algo 时**（`track_set_algo`）：自动把当前生效值**存回旧算法档案**，再**载入新算法档案** → 每个算法记住自己的调参，来回切不用重设。
- **硬件标定共享**：阈值 `threshold`、`white_ref`、`black_ref`、`file_log` 两算法通用，不进档案。
- **持久化**：`config.json` 改为 `{algo, file_log, threshold[], white_ref[], black_ref[], bb:{...}, pid:{...}}`；`save` 时先把当前生效值回存进当前算法档案再落盘。
- **向后兼容**：加载时先读老的根级 flat 键作为两档案基线，再用新的 `bb`/`pid` 覆盖 → 旧 config.json 不会丢参数（旧那套会同时灌进两个档案作起点）。
- `config` 命令现在打印两套档案（bb / pid）；`algo 0/1` 命令回显提示"已恢复该算法的 speed/slew/增益档案"。

### 涉及文件
- `sensor_debug/track_module.h`：`AlgoProfile` 结构 + `track_get_profile/track_load_profiles/track_capture_active` 声明
- `sensor_debug/track_module.cpp`：`_profile[2]` + `profile_capture/apply` + 改写 `track_set_algo`（切换即换档案）
- `sensor_debug/config_module.cpp`：`read_profile/write_profile` + 改写 `config_begin/save/print`（双档案+共享标定+向后兼容），JSON 缓冲 1024→2048、打印 buf 512→1024
- `sensor_debug/cmd_module.cpp`：`algo 0/1` 回显补充说明

### 验证方法
1. `algo 0` 设 `speed 17`；`algo 1` 设 `speed 20`；来回 `algo 0`/`algo 1`，确认 speed 各自恢复（17/20），不用重设。
2. `save` 后断电重启，`config` 看 `bb`/`pid` 两套是否都在、值正确。
3. 用旧 config.json 启动一次，确认参数没丢（被灌进两档案）。

## 问题：小车反应慢 + 调整过头（冲出赛道）

**用户反馈**：小车的反应速度很慢，调整的时候都调整过头。比如往左，就往左很多，全部都出了左边的道路。

---

## 诊断

### 症状本质：「反应慢 + 调过头」是同一个机制

当前控制是 **bang-bang（分段固定差速）+ slew（PWM 变化速率限制器）** 的组合。调试历史一直卡在反复调 `slewrate` 上：

- `slewrate=5000`（log10）→ 几乎没有平滑 → 高频小幅抖动（但能跑完一圈）
- `slewrate=300`（log-alg0-1）→ 平滑过度 → **19 秒内 3 次冲出赛道**，摆动不收敛、发散

**核心结论**：把 slew 调低 = 给电机指令加了延迟。控制回路里加延迟，必然出现教科书式的
**「反应变慢 → 补正滞后才生效 → 冲过头」**。

也就是说，「因为冲过头就把 slew 调低」的做法**反而会让冲过头更严重**——这就是一直走不出死循环的原因。

### 三个根本原因

**1. 治「过头」的地方选错了**

该减小的是**补正强度（差速比）**，不是**执行器速度（slew）**。
现在的 `sharp_ratio=-0.4 / xsharp_ratio=-0.6` 是让内轮大幅反转的非常激进的转向。
线只要稍微偏、碰到 CH7/CH8，车就立刻甩出一个急转（原地掉头式）→ 往左甩过头、冲出赛道左边。
这正是「往左就往左很多」的直接原因。

**2. bang-bang 本质上无法收敛**

分段式不管「偏了多少」都输出固定量，所以在中心附近必然过头，
做不到「偏一点就补一点」的比例响应。

**3. 最外侧的传感器没校准**

`sensor_module.cpp:10-19` 里 **CH1 / CH7 / CH8 的 threshold、white/black_ref 都是占位值（未校准）**。
而恰恰是这几个外侧传感器负责触发最激进的 SHARP/HAIRPIN（内轮反转）。
CH7/CH8 的 threshold=1500 比已校准通道（约 1100~1580）偏高 = **容易误判成白线**，
于是左侧会出现假的 HAIRPIN_L，让「往左冲过头」更容易发生。
log-alg0-1 一开头就往左一路 MEDIUM_L→SHARP_L→HAIRPIN_L 快速升级，也和这个吻合。

---

## 处理办法（按优先级）

### ① 减弱补正、同时让执行器反应更快（重点，先用命令试）

不改代码，用运行时命令就能试：

```
slewrate 1000      # 丢掉 300 那种延迟，让反应变快（消掉延迟造成的过头）
sharpratio -0.2    # 内轮反转从 -0.4 → -0.2
xsharpratio -0.3   # 发卡弯从 -0.6 → -0.3（应该最见效）
mediumratio 0.45   # 缩小相邻档落差（log10 里 4↔2 来回最多）
```

思路是「又快又柔」：既解决反应慢（slew 太低），又用差速比压住摆幅。

### ② 调试时先降速度

把 `speed` 从 17 调低，base PWM 下降，同样比例下过头会更温和，更好调。

### ③ 校准 CH1 / CH7 / CH8

用 `print on` 读各通道原始 ADC（白线上和黑地各一次），
再用 `threshold` / `whiteref` / `blackref` 逐路校准。
不做这一步，bang-bang 的外侧判定和后面的 PID 都不可信。

---

## 真正的结构性解法：校准后转 PID

`sensor_position_analog_from()` 和 PID 路径（`track_module.cpp:325`）已经实现好了。
PID 的比例项能做到「偏一点补一点、偏多补多」的连续响应，
**从根上消除 bang-bang 固定量的过头**。

但 PID 依赖 8 路模拟量加权准确，所以 **③的校准是前提条件**。

---

## 验证方法

跑一趟抓 log，用和 log10 相同的统计口径做数值对比：

- ≤10ms 切换占比
- 相邻档来回次数（如 4↔2、5↔3、7↔5）

每次只改一个参数、测一趟、对比统计口径，不要一次改多个，否则分不清是哪个参数起的作用。
