# 8路传感器扩展方案

**状态**：代码已按本文档实施完成（`sensor_module.h/cpp`、`track_module.h/cpp`、`cmd_module.cpp`、`config_module.cpp`），**尚未实车验证**。第9节"风险与待办"列的几项（尤其CH1/CH7/CH8阈值校准）是烧录后必须做的第一步。

**背景**：传感器模块是`AE-NJL5901AR-8ch`（8路一体），当前只用了中间5路（CH2~CH6），CH7/CH8因为接在ESP32的ADC2上，BT开启时ADC2读数会出错，一直标记"不可用"；CH1接在ADC1上本来就可用，只是没有接进代码。BT已经关闭（见"BT关闭"相关改动），ADC2的限制解除，现在可以把CH1/CH7/CH8也用起来，凑齐全部8路。

---

## 1. 物理布局（查了官方规格书确认）

`AE-NJL5901AR-8ch`规格书（`akizukidenshi.com/goodsaffix/ae-njl5901ar-8ch.pdf`）：

- 8路一字排开，**间距均匀16mm**（两端各留5mm边距，基板总长122mm = 5+16×7+5）
- "センサー数：右4、左4（合計8ch）"——以正中央为界，左右各4路，完全对称
- 顺序就是CH1→CH2→...→CH8依次排列

也就是说，CH1和CH8是**最外侧**的两路，比现在最外侧的CH2/CH6再往外扩一档（16mm）。完整物理顺序（未考虑180°反装）：

```
CH1 - CH2 - CH3 - CH4 - [正中央] - CH5 - CH6 - CH7 - CH8
```

## 3. 物理左右映射（延续180°反装的规律）

现有5路因为传感器机械反装180°，代码里做了镜像：`index 0(CH2)现在在右侧，index 4(CH6)在左侧`——也就是**channel号越小，物理位置越靠右**；channel号越大，越靠左。这个规律是整条传感器排一起反装的，扩到8路后同样成立，只是范围扩大：

```
物理左 ← CH8  CH7  CH6  CH5  |  CH4  CH3  CH2  CH1 → 物理右
        (idx7)(idx6)(idx5)(idx4) (idx3)(idx2)(idx1)(idx0)
```

`track_module.cpp`里读取`is_white[]`时按这个顺序取用（原来是`is_white[4]`=CH6=最左，`is_white[0]`=CH2=最右；现在是`is_white[7]`=CH8=最左，`is_white[0]`=CH1=最右）。

## 4. bang-bang：从2级差速扩展为4级差速

现有5路只有"缓转(mild)/急转(sharp)"两级，各自对应一对传感器（CH3/CH5缓转，CH2/CH6急转）。8路有更多档位可用，改成**4级差速**，两侧对称，按"越靠外、修正越猛"的既有设计思路自然延伸：

| 级别 | 触发传感器（左/右） | 内轮 | 外轮 | 说明 |
|------|---------------------|------|------|------|
| MILD（缓转） | CH5 / CH4 | `base × mild_ratio`（沿用现有`TURN_RATIO_MILD=0.7`） | `base`（不变） | 最内侧一档，跟现在的mild行为完全一样，只是触发传感器从CH3/CH5改成CH4/CH5 |
| MEDIUM（中转，**新增**） | CH6 / CH3 | `base × medium_ratio`（新参数，起调参考0.35，内轮减速但不反转） | `base`（不变） | 介于缓转和急转之间的过渡档，现有5路没有这一级 |
| SHARP（急转） | CH7 / CH2 | `base × sharp_ratio`（沿用现有参数，负值=反转，默认-0.4） | `base × turn_outer_ratio`（沿用现有参数，默认0.65） | 跟现在的急转行为一样，只是触发传感器从CH2/CH6改成CH2/CH7 |
| HAIRPIN（发卡弯，**新增**） | CH8 / CH1 | `base × xsharp_ratio`（新参数，起调参考-0.6，比sharp反转更狠） | `base × turn_outer_ratio`（复用SHARP的外轮比例，不新增参数） | 最外侧一档，专门应对R70~75mm发卡弯，比现在的SHARP更激进 |

**判定优先级**（沿用现有"由外到内、命中最外层就不再看内层"的if/else if结构）：
```
HAIRPIN_L (CH8) > SHARP_L (CH7) > MEDIUM_L (CH6) > MILD_L (CH5)
  > MILD_R (CH4) > MEDIUM_R (CH3) > SHARP_R (CH2) > HAIRPIN_R (CH1)
  > STRAIGHT（都不命中，或只有中间对CH4/CH5同时压线时的直行）
```

**新增2个运行时可调参数**（沿用现有`turnspeed`/`sharpratio`命令的模式，getter/setter+config持久化+cmd命令）：
- `medium_ratio`：MEDIUM级内轮速度比例（0~100%，起调参考35%）
- `xsharp_ratio`：HAIRPIN级内轮反转比例（0~100%，起调参考60%，语义同`sharpratio`，内部存负值）

**沿用不变**：`mild_ratio`(即`TURN_RATIO_MILD`，编译期常量，从未开放过运行时调整，这次也不改)、`sharp_ratio`、`turn_outer_ratio`。

## 5. PID：误差计算公式通用化

现有`sensor_position_from()`是专门按5路、中心index=2写死的：
```cpp
return (2 - sum / (float)count) / 2;
```

改成按实际路数`SENSOR_COUNT`通用化：
```cpp
const float center_index = (SENSOR_COUNT - 1) / 2.0f;  // 5路时=2，8路时=3.5
return (center_index - sum / (float)count) / center_index;
```
5路时代入`center_index=2`，公式退化成`(2-avg)/2`，跟现在完全一样，不影响已有行为；8路时`center_index=3.5`，值域仍然是-1.0~+1.0。

**顺带好处**：8路比5路能表达的离散档位更多（分母从2变成3.5，最小步进从0.25细化到约0.143，而且中间还有多路同时压线时取平均产生的中间值），误差信号比之前更接近连续量，对之前反复提到的"离散阶梯误差导致微分/高增益不稳定"这个老问题有一定缓解，但不是根治——PID重写时加的固定周期+微分滤波依然保留，两者是互补关系不是替代关系。

## 6. 丢线(lost)和十字路口(cross)判定：通用化

现有判定是硬编码5路：
```cpp
bool lost = !sharp_l && !mild_l && !center && !mild_r && !sharp_r;
bool cross = (sharp_l || mild_l) && (sharp_r || mild_r);
```

改成通用化（不依赖具体是5路还是8路，按"左半边"/"右半边"分组）：
```cpp
bool lost = true;
for (int i = 0; i < SENSOR_COUNT; i++) if (is_white[i]) { lost = false; break; }

bool left_any = false, right_any = false;
for (int i = 0; i < SENSOR_COUNT / 2; i++) if (is_white[i]) right_any = true;      // index越小越靠右（第3节的映射规律）
for (int i = SENSOR_COUNT / 2; i < SENSOR_COUNT; i++) if (is_white[i]) left_any = true;
bool cross = left_any && right_any;
```
8路时`SENSOR_COUNT/2=4`，即index0~3（CH1~CH4，物理右半边）和index4~7（CH5~CH8，物理左半边）各自分组判断。

## 7. 阈值：3路新增，需要实车重新校准

`sensor_module.cpp`的`THRESHOLD[]`需要从5个扩到8个。CH1/CH7/CH8是全新接入的3路，**现有5路的阈值经验值不能照抄**，每路器件公差不同，必须实车用`print on`看原始ADC白/黑值，再用`threshold`命令逐路标定——这一步是硬件相关的，没法在这份方案里预先给出准确数值，代码里会先放一个保守的占位默认值（比如沿用相邻已知路的量级），标注"未校准，需实车标定"。

## 9. 风险与待办

- **CH1/CH7/CH8的阈值完全未校准**，实施后第一件事就是`print on`看原始ADC值，逐路`threshold`标定，否则新3路可能一直误判白/黑
- **MEDIUM/HAIRPIN两档的比例（35%/-60%）是纯起调猜测**，没有任何实车依据，需要从这个起点开始试调，跟当年`sharp_ratio`/`turn_outer_ratio`第一次给默认值时一样
- **8路是否会让ADC2和ADC1混用出现读数干扰**，理论上BT关闭后ADC2应该没问题，但还没有实车验证过CH7/CH8读数是否稳定，实施后需要单独确认这两路的读数质量（比如`print on`看是否有异常跳变）
- **4级bang-bang的判定优先级和分级方案是本方案自己设计的**，不是沿用什么已验证的成熟方案，需要实车测试验证这个分级是否合理（比如MEDIUM这一档是否真的有必要、边界是否需要调整）
- 传感器间距变宽（8路span=7×16=112mm，比现在5路的64mm宽很多），最外侧CH1/CH8已经接近整条赛道白线宽度(19mm)的量级，需要确认车身宽度和赛道宽度是否容得下这么宽的检测范围，不会在正常直道上误触发HAIRPIN
