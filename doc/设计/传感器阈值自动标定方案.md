# 传感器阈值自动标定方案（whiteref / blackref / threshold 自动设置）

## 1. 背景与目标

现在每一路（CH1~CH8）的三个标定量都靠手动逐个设：

- `WHITE_REF[i]`：压线中心参考值（白线上，ADC 低值）
- `BLACK_REF[i]`：完全压不到线参考值（黑色背景，ADC 高值）
- `THRESHOLD[i]`：二值判断中点（白/黑分界）

流程是 `print on` 看原始 ADC → `whiteref/blackref/threshold CH VALUE` 逐路敲 → `save` 写 `config.json`。8 路 × 3 个量共 24 个值要人肉读、人肉填，慢且易错，换跑道/换环境光就得重来一遍。

**目标**：手持小车在跑道上移动几秒钟，一条命令自动算出全部 8 路的 white/black/threshold，打印结果，人工确认后 `save` 持久化。

关键极性（来自 `sensor_module.h:4`，NPN 光电管 active-low）：

> **白色 = 低 ADC 值，黑色 = 高 ADC 值。**

所以：
- `blackref` = 该路在**黑色下最"黑"的稳定值** → 采样里偏**大**的那一群
- `whiteref` = 该路在**白色下最"白"的稳定值** → 采样里偏**小**的那一群

## 2. 核心原理：极值群平均

你的思路（黑区取"最大的 100 个"平均、白区取"最小的 100 个"平均）本质是**取极值群的平均值**，这里说明为什么这样取比其他做法好：

| 取法 | 问题 |
|------|------|
| 全局单个 max / min | 一个毛刺尖峰就把 ref 带偏，抗噪差 |
| 全局所有样本平均 | 黑白混合采样时会被拉到中间，白/黑区被平均掉 |
| **极值群平均（top-K / bottom-K 平均）** | **既锁定极值区，又靠 K 个样本平均掉毛刺，兼顾"抓极值"和"抗噪"** ✅ |

- `blackref[i]` = 该路所有采样中**最大的 K 个**的平均
- `whiteref[i]` = 该路所有采样中**最小的 K 个**的平均

每一路独立计算（8 路各自维护自己的极值群）。

## 3. 两种采集方案

### 方案 A：两段式（你的原思路）

1. 把整排传感器放到**纯黑区**，敲 `calib black`，采集若干秒。
2. 把整排传感器放到**纯白区**，敲 `calib white`，采集若干秒。
3. 敲 `calib apply`，用采到的数据算出 8 路 white/black/threshold 并写入内存，打印结果。

- 黑段：每路 top-K 平均 → `blackref[i]`
- 白段：每路 bottom-K 平均 → `whiteref[i]`
- 优点：直观，符合直觉。
- 缺点：分两次、要保证整排都盖在同色区上，操作步骤多。

### 方案 B：扫描式（推荐）

手持小车在跑道上**来回扫过黑线**，让每一路都轮流经历黑线和白底，全程**单次**采集：

1. 敲 `calib sweep`（默认采 N 秒，如 5 秒 @100Hz = 500 样本）。
2. 在采集期间来回横扫黑线，保证每路都压过黑线也压过白底。
3. 时间到自动结束，对**每一路**分别算：
   - top-K 平均 → `blackref[i]`（该路扫到黑线的时刻）
   - bottom-K 平均 → `whiteref[i]`（该路在白底的时刻）
4. 自动导出 threshold，写内存并打印结果表。

- 优点：一次搞定 8 路，不用分黑白两次，最省事。
- 前提：扫描时每路都要既压到黑又压到白，否则该路对比度不足会被第 6 节的校验拦下。

> **推荐方案 B 作为主用法，保留方案 A 作为"整排盖同色"的备用/复核手段。** 两者共用同一套极值群平均内核，只是采集触发方式不同。

## 4. threshold 的自动导出

二值判断阈值由白/黑参考值线性插值得到：

```
threshold[i] = whiteref[i] + (blackref[i] - whiteref[i]) * ratio
```

- `ratio` 默认 `0.5`（取中点）。
- `ratio` 可调：偏小（如 0.4）判定更"倾向认为是白线"（更灵敏、易误判），偏大（如 0.6）更"保守"（更抗噪、易丢线）。默认 0.5 起调即可。

## 5. 关键参数

| 参数 | 建议默认 | 说明 |
|------|----------|------|
| 采样率 | 100 Hz | 复用主 loop 读 ADC 的节奏，10ms 一次 |
| 采集时长 | 3~5 秒 | 决定总样本数 N |
| 总样本数 N | 300~500 | N 应 ≥ 3~5 × K，保证极值群是"真极值"而非全部样本 |
| 极值群 K | 100 | 每路取多少个最大/最小值来平均 |
| threshold ratio | 0.5 | white/black 间插值系数 |
| 最小对比度 | 300（起调） | `blackref-whiteref` 小于此值判为标定失败（见第 6 节）|

> 注意 N 与 K 的关系：若 N=100 且 K=100，则"top-100"就是全部样本，退化成全局平均，失去抗噪意义。**必须 N 明显大于 K**，所以扫描/采集时长要够（≥3 秒 @100Hz）。

## 6. 健壮性校验（不合格不覆盖旧值）

自动标定最大的风险是"采歪了却照样写进去"。导出前对每一路检查：

1. **极性正确**：`blackref[i] > whiteref[i]`。否则该路接反/损坏/没采到，标定失败。
2. **对比度足够**：`blackref[i] - whiteref[i] ≥ 最小对比度`（如 300）。差值过小说明该路没同时经历黑和白（扫描没扫到 / 整排没盖住），标定不可信。
3. 任一路不合格：**打印哪几路失败、失败原因，且不写入任何值**（保留原有标定），让用户重采。或提供 `calib apply force` 强制写入（风险自负）。

这样能挡住"手抖没扫到某路""某路坏了""黑白放反了"这类典型翻车。

## 7. 内存与实现要点（仅方案，不含代码）

- **不需要保存全部样本**。每路只维护 K 个最大值和 K 个最小值即可：
  - 最省内存：`8 路 × 2（max群/min群）× K × sizeof(int)`。K=100 时约 `8×2×100×4 = 6.4 KB`，ESP32 完全够。
  - 维护方式：每路两个定长数组（top-K 用小顶堆 / min-K 用大顶堆，或简单插入排序数组），新样本只跟当前极值群的边界比较、决定是否替换，O(logK) 或 O(K)。
- **采集节流**：复用现有主 loop 的 `sensor_read()`，按 10ms 间隔取样，不要新开高频中断。
- **采集期间电机必须停**（避免抖动/移动影响，以及安全）。
- 采集完直接调用现有的 `sensor_set_white_ref / sensor_set_black_ref / sensor_set_threshold`（都是 memory-only），跟现有手动命令走同一条写入路径；持久化用新的 `savesensor`（见第 8.5 节）。

## 7.5 实现细节答疑（B 方案落地）

### Q1：5 秒能采集多少值？

- 采样率 100 Hz（每 10ms 一个 tick），8 路是**每个 tick 同时读 8 路**（`sensor_read()` 一次读全 8 路），不是轮流。
- 5 秒 = 500 个 tick → **每路 500 个样本**，8 路合计 4000 个。即 **N = 500**。
- 配 K=100 时，top-100 = "最黑的 20%"。**注意采样占空比坑**：扫描时某一路只有在被黑线压住时才读到黑值。若该路只有约 15% 时间压到黑线，top-20% 就会混进黑白边缘的灰样本，把 `blackref` 往白拉偏。
  - 对策（待定，见第 10 节）：**K 调小**（如 30~50，让极值群更"纯黑/纯白"），或 **延长扫描/多压几次黑线**（让 N 增大、黑样本占比提高）。`minK` 同理（白底占比通常更高，风险较小）。

### Q2：8 路集群，每一路的数据结构

每路要同时维护"最大的 K 个"（→ blackref）和"最小的 K 个"（→ whiteref），故每路两个定长数组 + 两个计数：

**K 必须运行期可配置**，但 C 数组要编译期定长，所以用"编译期容量 `MAX_K` + 运行期有效值 `K`"两级：

```
#define MAX_K 100                // 编译期容量上限（决定数组大小/内存占用，固定）
int K = 100;                     // 运行期有效极值群大小，1 <= K <= MAX_K，可配置

struct ChannelCalib {
    int maxK[MAX_K];  // 按 MAX_K 定长；实际只用前 K 个。升序存，maxK[0]=群里最小(淘汰边界)
    int minK[MAX_K];  // 同上，降序存，minK[0]=群里最大(淘汰边界)
    int maxCount;     // maxK 已填个数 (0..K)
    int minCount;     // minK 已填个数 (0..K)
};

ChannelCalib calib[8];           // 8 路各一份；内存 ≈ 8×2×MAX_K×4 = 6.4KB (MAX_K=100)
```

要点：
- **数组按 `MAX_K` 定长**（内存固定 6.4KB，取最坏情况），算法里所有"满没满"判断用**运行期 K**（`count < K`），而不是 `MAX_K`。改 K 只是改"用前几个格子"，不重新分配内存。
- 若想支持更大的 K（如 200），把 `MAX_K` 调大重编译即可；`calib k` 命令只允许设到 `1..MAX_K`，超范围报错。
- **每次 `calib sweep` 开始前要按当前 K 重置** `maxCount/minCount=0`（清空上次残留）。

设计要点：**数组头 `[0]` 永远是"最容易被淘汰的那个"**——
- `maxK` 升序存，头 = 群里最小 → 新样本要挤进"最大群"，只需打败这个最小的；
- `minK` 降序存，头 = 群里最大 → 新样本要挤进"最小群"，只需打败这个最大的。

淘汰只看头，判断成本 O(1)，插入 O(K)（数组）或 O(logK)（堆）。N=500、K=100 下两者都是瞬间完成，**推荐直接用升/降序数组，简单不易错**。

### Q3：如何去掉旧值取新的值（top-K 维护）

对每个新样本 x，两组各判一次，核心就是"**淘汰的永远是当前极值群里最不极端的那个（数组头）**"：

- **maxK（留最大的 K 个）**：未满 → 按升序插入；已满 → 若 `x > maxK[0]`（当前留下的最小值）则**踢掉 maxK[0]**、把 x 插到正确位置维持升序；`x ≤ maxK[0]` 直接丢弃。
- **minK（留最小的 K 个）**：镜像——已满 → 若 `x < minK[0]`（当前留下的最大值）则踢掉 minK[0]、把 x 插到正确位置维持降序；否则丢弃。

### Q4：算法（伪代码）

```
int N = 0;   // 总采样 tick 数，供结果表显示、判断样本是否够

// ---- 采集期：每个 10ms tick 调一次 ----
onTick():
    vals[8] = sensor_read()
    N++                              // 累计总样本数
    for i in 0..7:
        pushMax(calib[i], vals[i])   // 更新该路"最大K个"
        pushMin(calib[i], vals[i])   // 更新该路"最小K个"

// 插入到升序数组 maxK：保留最大的 K 个
pushMax(c, x):
    if c.maxCount < K:
        insertAscending(c.maxK, c.maxCount, x)   // 找位置、后移、插入
        c.maxCount++
    else if x > c.maxK[0]:                        // 打败当前最弱者才进
        removeHead(c.maxK, c.maxCount)            // 去掉旧值(头=最小)，整体前移
        insertAscending(c.maxK, c.maxCount-1, x)  // 取新值，插回维持升序
        // maxCount 不变，仍为 K

// 插入到降序数组 minK：保留最小的 K 个（镜像）
pushMin(c, x):
    if c.minCount < K:
        insertDescending(c.minK, c.minCount, x)
        c.minCount++
    else if x < c.minK[0]:
        removeHead(c.minK, c.minCount)
        insertDescending(c.minK, c.minCount-1, x)

// ---- 采集结束：导出每路参考值 ----
finalize():
    for i in 0..7:
        black = average(calib[i].maxK, calib[i].maxCount)   // 最黑的一群
        white = average(calib[i].minK, calib[i].minCount)   // 最白的一群
        // 校验（第 6 节）
        contrast = black - white
        if black <= white or contrast < MIN_CONTRAST:
            mark FAIL(i); continue                          // 不写该路，保留旧值
        thr = white + round(contrast * ratio)               // ratio 默认 0.5
        sensor_set_white_ref(i, white)
        sensor_set_black_ref(i, black)
        sensor_set_threshold(i, thr)
    printResultTable(N, K)          // 表头必须打印总样本数 N 及 N/K 比值
    hint("全 OK 后用 savesensor 持久化传感器值")
```

> 备选实现：`maxK` 用小顶堆、`minK` 用大顶堆，替换成本降到 O(logK)。但本场景数据量小，数组版足够，优先取可读性。

## 8. 命令接口设计（沿用现有 `strncmp`+`sscanf` 风格）

方案 B（推荐）：

```
calib sweep [seconds]     启动扫描式采集，默认 5 秒；结束后自动算白/黑/阈值、打印结果表、写内存
```

方案 A（备用）：

```
calib black [seconds]     采集黑区样本（整排盖黑）
calib white [seconds]     采集白区样本（整排盖白）
calib apply               用已采黑/白样本导出并写内存
calib apply force          校验不过也强制写入
```

可选调参：

```
calib ratio VALUE         设置 threshold 插值系数（默认 0.5）
calib k VALUE             设置极值群 K，范围 1~MAX_K（默认 100）；超范围报错，memory only
calib show                打印当前 K / ratio / 默认扫描秒数
```

`calib k` 行为（跟现有 `whiteref/threshold` 命令一致的风格）：
- 校验 `1 <= VALUE <= MAX_K`，否则回 `>>> Usage: calib k VALUE (1~MAX_K)`。
- 只改内存里的运行期 `K`，回显 `>>> K set to VALUE (memory only, use save to persist)`。
- 下次 `calib sweep` 生效。

**持久化**：K、ratio、默认扫描秒数是标定参数（旋钮），跟随 `save` 写进 `/config.json`（新增标量键 `calib_k` / `calib_ratio` / `calib_sweep_sec`），`config_begin()` 启动读回，沿用 `config_module` 现有标量键读写方式（见 `config_module.cpp`）。white/black/threshold 三个数组则由 `savesensor` 独立保存（见第 8.5 节）。

采集结束统一打印形如下表（举例），**必须在表头显示总采样数 N**，并提示用 `savesensor` 持久化：

```
>>> Calibration result (memory only, use 'savesensor' to persist):
>>> Samples: N=500 (5.0s @100Hz), K=100   [N/K=5.0, 建议 N/K >= 3~5]
CH  white  black  thr    contrast  nBlack  nWhite  status
1   612    2380   1496   1768      143     357     OK
2   660    2410   1535   1750      120     380     OK
...
7   1490   1520   ----   30        6       210     FAIL(low contrast)
>>> CH7 未通过校验，请重采或检查该路接线。
```

表头/表列的用途（**显示 N 是硬性要求**，让你一眼判断样本是否够）：

- **N**：本次采集的总 tick 数（每路样本数），配 `N/K` 一起显示。`N/K < 3` 说明极值群几乎等于全部样本、退化成全局平均，需延长采集时间。
- **nBlack / nWhite**（每路，可选但强烈建议）：该路分别有多少个样本"明显偏黑 / 明显偏白"（比如以本路当前 black/white 的中点为界统计）。这比全局 N 更能暴露问题——**某路 nBlack 太小（如 CH7 只有 6）说明它根本没扫够黑线**，即使全局 N 很大也不行。理想是 nBlack、nWhite 都 ≥ K。

传感器值的持久化用**独立命令 `savesensor`**（不再混进 `save`），详见第 8.5 节。

## 8.5 传感器值独立保存：`save` 与 `savesensor` 拆分

### 动机

现在 `config_save()` 把**全部内存状态**（算法参数 + 传感器三数组）一次写满 `config.json`（见 `config_module.cpp:143-176`）。问题：调 PID/速度想 `save` 时，会**连带把内存里还在试验、没确认好的传感器值一起写死**；反过来标定完想存传感器值，又会把其它参数一起落盘。两类值该各存各的。

### 拆分后的职责

| 命令 | 保存内容 | 不动 |
|------|----------|------|
| `save` | 只存**非传感器**值（algos/active/file_log/lograte + `calib_k`/`calib_ratio`/`calib_sweep_sec`）| 不动 threshold/white_ref/black_ref |
| `savesensor` | 存**全部**三类传感器值（white + black + threshold）| 不动其它参数 |
| `savesensor white` | 只存 white_ref | 其余全不动 |
| `savesensor black` | 只存 black_ref | 其余全不动 |
| `savesensor threshold` | 只存 threshold | 其余全不动 |

> 注：`calib_k`/`calib_ratio`/`calib_sweep_sec` 是标定**参数**（旋钮），不是测得的传感器值，归 `save`。

### 实现方案（关键：避免单文件互相覆盖）

`config.json` 是**单个文件**，`serializeJson(doc, f)` 以 `"w"` 打开会整文件重写。若 `save` 只构建非传感器键就写盘，会**把文件里已有的传感器数组抹掉**。两种解法：

**方案①（推荐）分文件**——传感器值独立存 `/sensor.json`，参数仍存 `/config.json`：
- `save` → 只写 `/config.json`（`build_config_doc` 里**去掉** threshold/white_ref/black_ref 三段）。
- `savesensor [which]` → 只写 `/sensor.json`；带参数时只更新对应数组（读现有 `/sensor.json`→改指定段→写回，保住另两段）。
- `config_begin()` 启动时**两个文件都读**：先读 `/config.json` 参数，再读 `/sensor.json` 传感器值。
- **向后兼容**：若 `/sensor.json` 不存在，回退读旧 `/config.json` 里内嵌的 threshold/white_ref/black_ref（老配置照常能用）；下次 `savesensor` 会迁移到新文件。
- 优点：各命令独占一个文件，**零覆盖风险**，逻辑最简单。

**方案②单文件读-改-写合并**——仍只用 `config.json`：
- 每个 save 变体都先 `deserializeJson` 读回现有文件，只覆盖自己负责的键，其余原样保留，再写回。
- 优点：不新增文件；缺点：每次 save 都要多一次解析、代码更绕，容易漏键。

推荐**方案①**。

### 命令行为（沿用现有风格）

```
save                      保存非传感器参数（不动传感器值）
savesensor                保存全部传感器值（white+black+threshold）
savesensor white          只保存 white_ref
savesensor black          只保存 black_ref
savesensor threshold      只保存 threshold
```

- 非法参数回 `>>> Usage: savesensor [white|black|threshold]`。
- 成功回显各自保存了什么，例如 `>>> Saved white_ref to /sensor.json`。
- 帮助文本(`help`)、`config` 打印视图需同步说明两条命令的区别。

## 9. 完整使用流程（方案 B）

1. 停车、上电，用 **USB 串口**连上小车（命令输入/回显都走 `Serial`，见 `cmd_module.cpp:16`）。
2. 敲 `calib sweep 5`。
3. 5 秒内手持小车（**带着 USB 线**）在跑道上来回横扫黑线，保证每路都压过黑与白。USB 线要留足长度、别扯到接口。
4. 看打印的结果表：先看表头 **N 和 N/K**（样本够不够），再确认 8 路全 OK、对比度合理、每路 nBlack/nWhite 都够（≥K）。
5. 有 FAIL 的路：重采（回到步骤 2）或检查接线。
6. 全 OK 后敲 `savesensor` 持久化传感器值（写 `/sensor.json`，不影响其它参数）；只想存某一类可用 `savesensor white`/`black`/`threshold`。
7. `print on` 抽查几个位置的 `sensor_position_analog` 是否合理。

## 10. 待确认 / 可选后续

- **K 与采样占空比的权衡（重点，来自 Q1）**：5 秒 @100Hz → 每路 N=500。扫描式下每路压到黑线的时间占比不高，K=100（top-20%）可能混进边缘灰样本、把 blackref 拉偏。待实车确认：是 **把 K 调到 30~50**，还是 **默认扫 8~10 秒**，或两者都做。
- 采集默认时长、K、ratio 的最终取值，需实车跑一次看结果表微调。
- 是否需要"每路单独重采"命令（只补标定失败的那几路），还是每次都全采。
- 是否要把标定原始极值群平均值也打到日志（`ram_log`）里，方便事后复盘。
