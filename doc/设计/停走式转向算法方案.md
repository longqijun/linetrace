# 停走式（脉冲）转向算法方案

> 提出人：用户。动机：觉得 bang-bang "一次执行过长"，转向时车带着惯性冲过头。想法是把转向动作**切成有时间上限的小段，每段结束先停车、再重新看传感器、再动**。
> 本文先忠实记录该算法，再评价它有没有意义。

## 一、算法描述（按用户设想）

1. **中心区照常**：CH4 / CH5 检测到（直行）时，正常连续运行，不做任何切段。
2. **转向切段**：**除 CH4/CH5 外**，其它 CH 检测到（即需要转向、要控制速度）时：
   - 执行该转向动作，**单次最多运行 200ms**；
   - 200ms 到 → **先 STOP（停车）**；
   - 停稳后**重新读传感器**；
   - 再根据新读数**重新运行**下一段（继续转 / 换档 / 回直行）。
3. 如此"**转一小段 → 停 → 看 → 再转一小段**"循环，直到回到中心区（CH4/CH5）恢复连续直行。

### 状态机 / 伪代码
```
loop:
  read sensors
  if 中心(CH4/CH5):
      连续直行（不切段）
  else:  // 需要转向
      state = TURN
      t_start = now
      执行转向动作(该档的L/R)
      while now - t_start < 200ms:   // 单段上限
          （可选：期间是否继续读传感器调整？—— 见第四节设计选择）
      motor_stop()                   // 先停
      settle + read sensors          // 停稳后重新看
      // 回到 loop 顶部，用新读数决定下一段
```

## 二、先澄清一个前提（避免误解）

现有 bang-bang **并不是"一次执行很久"**：`track_update()` 每个 loop（实测约 1ms 一圈）都会重读传感器、重算档位、重设 PWM。所以它**每 ~1ms 就重新决策一次**。

那"感觉执行很久"是怎么回事？是因为——**车带着惯性冲过头时，传感器持续读到同一个边缘状态（比如一直是 HAIRPIN 或 LOST），于是"同一个决策"被重复了几百毫秒**（日志里见到过 800ms~1s 的长反转 thrash）。

所以你这个算法真正改变的**不是"执行时长"，而是"惯性"**——用 STOP 打断"车还在冲、传感器还在读同一边缘、于是继续同一动作"的恶性循环。理解这一点，才好评价它。

## 三、评价：有没有意义？——有，而且抓到了几个真问题

### ✅ 有价值的点
1. **STOP 杀惯性 → 直接治"冲过头"**：日志里每次翻车都是"冲进弯→过头→丢线→盲目找线甩飞"。停车把动能清零，是最直接对症的一招。
2. **停稳后再读传感器 → 读数干净、无运动滞后**：正好回应你之前担心的"前探/高速时传感器数据乱、像冲出去了"。静止读数没有运动模糊/滞后，位置最准。
3. **200ms 上限 → 封顶"盲目段"时间**：避免日志里那种 800ms~1s 的长反转 thrash（`log20` 行 807 有过 dt=1011ms）。把每次"看不清就乱掰"的时间钉死在 200ms 内，是好事。
4. **⭐ 最妙的一点——用"跑/停占空比"绕开电机死区来降速**：你这台车最大的墙是**静摩擦死区大、PWM 低于 ~102 转不动、所以降不了速**（见 `../硬件/如何判断当前有没有机械延迟.md`、`../日志分析/log20分析.md`）。而"跑一下停一下"**用时间占空比降低平均速度**——每段仍以能转动的 PWM 跑，但平均速度被 stop 段拉低。**这等于在宏观层面做 PWM 调速，恰好绕开了低 PWM 死区**。这是对症那面硬件墙的一个真思路，比方案A（直接降 PWM，被死区顶死）更有可能真的把弯道速度降下来。

### ⚠️ 问题与风险（尤其在你这台死区大的车上）
1. **重启死区是最大障碍**：每次 STOP 后要**从静止重启**，而转向档外轮只有 70、内轮反转 -64，**都低于静摩擦"起步阈值"(~102)** → 很可能**停了就起不来 / 卡住抖动**。要让停走可行，**每段重启必须"踢一脚"**（先给一下满 PWM 冲过静摩擦，再落回目标值）。**不加 kickstart，这个算法在你车上大概率第一次停完就不动了。**
2. **200ms 可能仍偏长**：以当前车速，200ms 能跑不短的距离——**过头可能在这 200ms 之内就已经发生**，等停下来再看已经晚了。建议**单段更短（先试 50~120ms）且做成可调**。
3. **停不是瞬间**：车有惯性，STOP 后还会滑一小段才真停；"停后读"要等它真停稳，否则读的还是运动中的位置。这段 settle 时间也要留、也要调。
4. **慢 + 顿挫**：停走停走整体慢、机械冲击大、对齿轮/电机不友好；竞速场景会明显拖慢圈速。
5. **不治本**：本质是"拿速度/平顺换控制"，根子（死区/转弯能力）没变。

### 结论
**这个算法有意义，值得做成一个独立算法（比如 `algo 2`）原型验证**——它同时命中了"杀惯性、干净读数、封顶盲目段、绕开死区降速"四个真问题。但在你这台车上，**成败取决于两件配套**：
- **必须加"重启踢一脚"(kickstart)**，否则停完起不来；
- **单段时间要更短且可调**（200ms 可能太长），停车 settle 时间也要可调。

而且要意识到：它**和"给电机加 kickstart 降死区"其实殊途同归**——两者都是在解决"低速/重启转不动"。所以有个更简的替代路线值得先试：**先把 kickstart 做进现有电机驱动**（让车能稳定跑更慢），说不定不用停走、方案A/PID 降速就直接生效了。停走式则是"如果连 kickstart 都压不到够低的速度"时的更激进备选。

## 四、若要实现——几个设计选择（需你定）
1. **单段内是否继续读传感器？**
   - (a) **纯提交**：200ms 内闭眼执行选定动作，到点才停再看 → 最简单，但盲。
   - (b) **段内也读、可提前结束**：读到已回中心就提前停 → 更聪明，但就接近"现有 bang-bang + 强制周期性 STOP"了。
2. **单段时长**：建议参数化 `pulseturn N`(ms)，先试 80~120，别锁死 200。
3. **STOP 方式**：滑行停(coast, PWM=0) 还是 刹车停(brake)？刹车停得快、读数早，但更冲击。
4. **停车 settle 时长**：停多久算"停稳可读"，参数化 `pulsesettle N`(ms)。
5. **重启 kickstart**：起步先给多大 PWM、给多久，参数化。
6. **只对哪些档生效**：全部转向档，还是只对 SHARP/HAIRPIN（发卡最需要，MEDIUM 缓弯没必要停走）？建议只对急档，缓弯别停走。
