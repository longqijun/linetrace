# LOG 高频采样方案（增加打印频率）

> 状态：**已实现（2026-08-09），待编译/实车验证**。默认 `lograte=10ms`，全局(不进算法档案)，`save` 持久化；记录已改为**只写内存、不走串口**。
> 需求：现在的 log 只在"档位变化"时记（+ 每 500ms 心跳），会漏掉同档内的传感器细节（见 `../日志分析/log解析答疑.md` Q5/Q6）。希望**提高打印频率、别漏掉每一次 loop**，先确认内存扛得住。

## 一、现状（事件触发 + 心跳）
`track_module.cpp` 里记录条件：
```c
mode_changed  = (本次mode != 上次mode);
heartbeat_due = !mode_changed && (now - _last_log_ms >= HEARTBEAT_INTERVAL_MS);  // HEARTBEAT_INTERVAL_MS=500
if (mode_changed || heartbeat_due) 写一行;
```
- 只有档位变化才记；同档期间最多每 500ms 补一条心跳。
- 优点：省内存，长直道也不刷屏。缺点：同档内的位置漂移看不到（Q5/Q6）。

## 二、内存现实（先算清楚，再决定频率）
RAM 日志缓冲（`ram_log_module.cpp`）：
- **20KB 一块，最多 16 块 = 最大 320KB**；**开机时按空闲堆分**，实际可能只有一两百 KB。
- **写满就停、不覆盖旧的**（满了静默丢弃）。→ 满了这趟就不再记录。
- 每行约 **22 字节**（bangbang），PID 行带 err 约 **28 字节**。
- 用 **`mem` 命令**可看到实际分到多少（打印 "ram log buffer: N bytes"）。

### 不同频率能撑多久（按 22 字节/行估）
| 记录频率 | 行/秒 | ~KB/秒 | 320KB 撑 | 160KB 撑 |
|---|---|---|---|---|
| 每 loop(~1ms) | ~1000 | ~22 | ~14s | ~7s |
| 每 5ms | ~200 | ~4.4 | ~70s | ~35s |
| **每 10ms** | ~100 | ~2.2 | ~**130s** | ~65s |
| 每 20ms | ~50 | ~1.1 | ~260s | ~130s |
| 当前(事件+500ms心跳) | ~10-15 | ~0.3 | 很久 | 很久 |

**结论**：一圈 ~10s。
- **每 loop(1ms)**：只够录 **~1 圈**就满停 → **跑整趟内存不够**。
- **每 10ms**：能录 **完整一趟(100s+)**，且车 10ms 才走几毫米，几乎不漏轨迹。← 甜点

### 额外注意：串口会拖慢 loop
如果记录时**串口输出(print usb/bt)开着**，每条还要走串口，115200 下一行 ~2ms → 每 loop 打印会把 loop 拖慢好几倍、**扰乱控制本身**。
→ 高频记录时应 **`print off`（只写 RAM）**；RAM 写入是 memcpy，很快，不扰动。

## 三、本方案（已定两点）

### 3.1 采样周期做成可配置参数：`lograte N`(ms)
- 把原来写死的 `HEARTBEAT_INTERVAL_MS=500` 改成**运行时变量**，加命令 `lograte N`（单位 ms）。
- 语义：**档位变化立即记 + 同档内每 N ms 补一条**。N 越小越密。
- 常用值：`lograte 1`（每 loop 级，抓瞬态用，注意内存只够 ~1 圈）、`lograte 5`、`lograte 10`（整趟连续轨迹，推荐日常）、`lograte 500`（恢复省内存）。
- 跟其它参数一样：可 `save` 持久化；开机默认建议 **10ms**（能录整趟又几乎不漏）。
- 边界：N 太小会很快写满缓冲（见第四节表），命令里做下限保护即可（如 N≥1）。

### 3.2 记录只写内存，不打串口
- 现在每记一条会同时 `ram_log_append()` + `out_usb()` + `out_bt()`（串口实时流）。**高频时串口流会把 loop 拖慢好几倍、还刷屏。**
- 改成**只 `ram_log_append()`，去掉 track 记录路径里的 `out_usb/out_bt`**。
- 效果：RAM 写入是 memcpy，极快，**不扰动控制**；跑的时候串口安静，结束后用 `log dump` 一次性看。
- 这也正好符合设计初衷"track on~off 全程只写内存，off 时再备份到 flash"。

## 四、各周期能录多久（只写RAM后，1ms 也不受串口限制，只受缓冲限制）
| `lograte` | 行/秒 | ~KB/秒 | 320KB 撑 | 160KB 撑 | 用途 |
|---|---|---|---|---|---|
| 1 | ~1000 | ~22 | ~14s | ~7s | 抓几秒瞬态(只够~1圈) |
| 5 | ~200 | ~4.4 | ~70s | ~35s | 大半趟细看 |
| **10** | ~100 | ~2.2 | ~130s | ~65s | **整趟连续轨迹(推荐默认)** |
| 500(旧) | ~10-15 | ~0.3 | 很久 | 很久 | 省内存 |

跑前用 `mem` 看实际缓冲大小，按此表估能录多久。

## 五、实现要点
- **track_module.cpp**：
  - `HEARTBEAT_INTERVAL_MS`(500) → 改为运行时变量 `_log_interval_ms`（默认 10），加 `track_get/set_log_interval()`。
  - 记录判定里的 `>= HEARTBEAT_INTERVAL_MS` 换成该变量。
  - 记录写出处**删掉 `out_usb(rec); out_bt(rec);`，只保留 `ram_log_append(rec);`**。
- **cmd_module.cpp**：加 `lograte N` 命令（下限 1）+ help 一行。
- **config_module.cpp**：`_log_interval_ms` 进持久化（`save`/`config`/PARAMS 行可选加 `lograte=N`）。
- 日志**格式不变**，解析脚本/分析不受影响；H 行 dt 语义不变，只是变密。
- （可选）是否把 `lograte` 也纳入"每算法档案"？—— 建议**不纳入**，它是全局调试选项，不是算法调参，放全局单值即可。
