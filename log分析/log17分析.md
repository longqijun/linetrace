# log17 数据分析报告（弯道测试，bang-bang，跑几圈后冲出）

> 背景：上弯道测试，跑了若干圈后冲出去。本次运行 **64.5 秒 / 732 行**，是目前跑得最久的一次。
> ⚠️ **本次用的是 bang-bang，不是 PID**：PARAMS `algo=BANGBANG`，speed=17, medium_ratio=0.65, sharp_ratio=-0.20, xsharp_ratio=-0.60, slew_rate=5000。**（直线上跑得极稳的是 PID/log16，弯道这次却切回了 bang-bang——见第五节建议）**

## 一、总体：能跑，但在"丢线→找回"的刀尖上跑

好消息：bang-bang **能把带弯的赛道跑下来若干圈**（64s 才出事），直线段和缓弯稳稳的 108/108。
坏消息：**几乎每个急弯都在"丢线→大幅反转找线→勉强找回"**，全程 `00 A`(LOST_L)/`00 B`(LOST_R) 出现 **50+ 次**——等于每个急弯都擦边险过，靠运气续命，直到某次没救回来就飞出去。

## 二、每个急弯的典型剧本（反复出现）

以一段为例（行 63–68）：
```
0C 4 (CH3,中转) → 0E 6 (CH2/CH3,急转) → 0F 8 (CH1..,发卡,内轮-31)
→ 00 B (丢线,右侧) → 内轮猛反转-54/-21 原地找 → 794ms 后 01 8 找回
```
- 车速恒定 108，进急弯**来不及转** → 线甩到最外侧 CH1/CH8（发卡档）→ 内轮反转 -31~-64 猛掰 → 还是**冲过头把线丢了**（`00 A/B`）。
- 丢线后靠 `LOST` 分支原地大幅**反转找线**，常要 **500~800ms** 才找回（行 68 dt=794、行 519 dt=824、行 601 dt=661…）。这段时间车基本在原地打转赌线还在附近。
- 大多数弯靠这套"险过"了，但这是**在极限边缘**，不是稳定跟踪。

## 三、最后冲出去的经过（行 746–778）

```
30 3→0E 6→0F 8(发卡) → 00 B(丢线右) → E440找线 → 00 A(又丢到左)
→ 80 7 / C0 7 内轮-64 乱掰 → 一串混乱多路pattern(C8/41/09/4F)
→ FF(8路全白) → 00 A LOST → 00 C LOST_STOP
```
- 在一个急弯（很可能是 S 弯或连续发卡）处，车先冲到右侧丢线，找线的大幅反转把它**甩向左侧又丢**，两次找线方向打架、越掰越乱，最后整片压到 **`FF`（8 路全白）= 冲出赛道进入白区**，彻底丢线停车。
- **本质是一次"失败的找线"**：找线是盲目大幅反转，赌线在旁边；这次赌错了方向/幅度，直接把车甩出赛道。

## 四、根因

1. **恒速太快、进弯来不及转**：speed=17 全程不变，直线够用，但急弯需要更早更狠地转，车却以直线速度冲进弯，必然冲到最外侧甚至丢线。
2. **bang-bang 是"到边缘才反应"的被动式**：等线到 CH1/CH8 才发卡反转，已经晚了；反转又猛（-64），容易冲过头。
3. **丢线找线太盲目/太violent**：靠原地大幅反转赌线的位置，500~800ms 才找回，且方向可能猜错——最后就是猜错方向飞出去。
4. **离散档 + 反转在弯道天生边缘**：和直线的死区极限环同源，弯道上表现为"每弯必险"。

## 五、建议（按优先级）

### 1. 弯道也上 PID（首选，但要提高 kp）
直线证明 PID 连续修正远稳于 bang-bang。但**注意 PID 现有增益弯道会不够劲**：
- 现 kp=40，误差最大 ±1 时输出仅 ±40，内轮最多降到 `108-40=68`，**永远不反转**——**发卡弯根本转不过来**（bang-bang 发卡是内轮 -64）。
- 要让 PID 在急弯也能把内轮压到反转，kp 需大得多（粗算要 ~150 以上才能在满误差时反转），但那样直线会很躁。
- **解法**：① 提高 kp 到能过弯的程度 + 靠 slew/kd 压住直线抖动；或 ② **增益调度**（直线低 kp、误差大时切高 kp/或切 bang-bang 反转）；或 ③ **PID 缓弯 + bang-bang 发卡** 的混合。先把 kp 往上试（如 60→80→100），看弯道够不够、直线还稳不稳。

### 2. 弯道降速（强烈建议，独立于算法）
- 全局把 speed 降一档（17→13 试），先换稳定性。
- 更好：**按误差降速**——误差大（在弯）时自动减 base，误差小（直线）时提速。这是竞速车标准做法："直道冲、弯道收"。进弯慢下来，就不会冲到丢线，也就不需要那套危险的找线。

### 3. 让"找线"不那么盲目/致命
- 当前丢线靠大幅反转赌方向，赌错就飞。可**减小找线反转幅度**、或**缩短 LOST 超时**更早停而不是乱掰，避免"失败找线"把车甩出赛道。
- 治本还是第 2 条：进弯别冲到丢线，就不用赌。

### 4. 传感器前探
弯道对"提前量"最敏感，传感器阵列往前移能更早看到弯、更早转，缓解"进弯来不及"。

## 六、结论

bang-bang 已经能把带弯赛道跑若干圈，但**每个急弯都在丢线边缘险过**，最后一次找线猜错方向就冲出赛道（`FF` 全白）。这不是稳定跟踪，是刀尖续命。
**下一步最该做两件事：① 弯道也用 PID（并把 kp 提到能过发卡的程度，或做增益调度/混合）；② 弯道降速（最好按误差自动收速）。** 先做这两条，再谈找线和传感器前探。

## 七、"恒速冲进弯"的详细解决方案：动态弯道降速

**核心思想**：把"全程恒定 `base`"改成"**随弯度动态调整的 base**"——直道满速冲、弯道自动收速。进弯慢下来，车就不会冲到最外侧丢线，所需的转向力度也随之下降，连带缓解了 log17 里"每弯必险 + 危险找线"的整条链。

现状（`track_update()`）：`base` 是恒定的
```cpp
int base = motor_level_to_pwm(config_get_speed());   // 全程不变
```
下面按"由易到难/由稳到激进"给三层方案，可单独用，也可叠加。

### 方案 A：按档位分级降速（bang-bang 用，改动最小、最直接）
线离中心越远（档位越急），forward 速度压得越低。给每档一个速度系数：

| 档位 | pattern 触发 | speed_factor（建议起调） |
|---|---|---|
| STRAIGHT / 中心 / CROSS | CH4/CH5 | 1.00（满速） |
| MEDIUM(3/4) | CH3/CH6 | 0.85 |
| SHARP(5/6) | CH2/CH7 | 0.65 |
| HAIRPIN(7/8) | CH1/CH8 | 0.50 |

实现：把恒定 `base` 换成"档位内先算有效 base 再算轮速"。示意：
```cpp
int base_max = motor_level_to_pwm(config_get_speed());
// ...判定出档位后，取该档 speed_factor...
int base_eff = (int)(base_max * speed_factor);
// 转向档的外轮、内轮反转都基于 base_eff 算，而不是 base_max：
pwm_r = (int)(base_eff * _turn_outer_ratio);   // 外轮
pwm_l = (int)(base_eff * _xsharp_ratio);       // 内轮反转(发卡)
```
要点：**关键是连 forward/外轮一起降**，不能只降内轮。建议把这几个系数做成可运行时调（如复用/新增命令），实车对着弯道试。
- 小改进（更早收速）：**线一离开中心(进 MEDIUM)就开始降**，给机械留提前量，别等到 SHARP/HAIRPIN 才降——那时已经冲到边缘了。

### 方案 B：按误差连续降速（PID 用，最平滑，推荐）
PID 有连续误差 `error`（-1~+1），直接用它线性压 base：
```cpp
float abs_err = fabsf(error);
int base_max = motor_level_to_pwm(config_get_speed());
int base_min = /* 防失速地板速，如 base_max*0.45 */;
int base_dyn = base_max - (int)(_corner_slow * base_max * abs_err); // _corner_slow: 0~1
if (base_dyn < base_min) base_dyn = base_min;

pwm_l = clamp_pwm(base_dyn + _pid_hold_output);
pwm_r = clamp_pwm(base_dyn - _pid_hold_output);
```
- `_corner_slow` 建议起调 0.5：`err=0`(直道)→满速；`err=±1`(弯到边)→base 降到约 50%。做成运行时可调（如新增 `cornerslow N` 命令）。
- `base_min` 地板速防止弯中太慢失速/被静摩擦卡住。
- **协同效应**：进弯降速后，跟住同一半径**所需的转向量变小**——PID 可能不必把内轮压到反转（见第五节 kp 难题就缓解了）。即"用降速换转向力度"，两者是此消彼长的。

### 方案 C：预测式降速（进阶，锦上添花）
反应式降速（已偏/已进弯才降）仍略晚。更进一步：
- **按误差变化率提前刹车**：`|d(error)/dt|` 大（线正快速往边缘冲）时就预降速，等于用微分做"预判刹车"，比等 `|error|` 大了再降更早。
- **传感器前探**（硬件）：阵列往车头前移，等于提前一段距离看到弯，`error` 提早上升→降速提早触发。对"进弯来不及"最对症。
- **降齿轮比**（硬件，见机械延迟文档第七节）：响应快了，同样车速也更转得过来。

### 配套注意
1. **降速与转向要用同一个 base_eff/base_dyn**：外轮、内轮、PID 差速都基于降后的 base 算，否则一边降速一边按满速转，会打架。
2. **平滑过渡**：base 的变化经由已有 slew 下发即可，别让 base 突跳造成顿挫（slew=5000 足够快，够平滑）。
3. **先小步试**：先只上方案 A 或 B 的一个系数，跑同一弯道对比 log 的丢线次数（`00 A/B` 计数）是否明显下降，再叠加。
4. **和第五节合起来看**：**弯道 PID + 按误差降速(方案 B)** 是最推荐组合——PID 负责平滑连续修正，降速负责让"需要的修正量"落在 PID 能力范围内，互相补足。

### 一句话
把恒定 base 改成"**直道满速、弯道按档位/按误差自动收速**"，进弯不再冲到边缘，丢线和危险找线随之消失。最小改动走方案 A（bang-bang 分级），最平滑走方案 B（PID 按误差），进阶再叠预测式与传感器前探。

#### ⚠️ 重要约束：电机死区太大，方案A降速空间很有限
实测**车速不能小于 speed 16（即 PWM<~102 起步转不动）**，静摩擦死区很大。为此加了两层保护：
- **外轮最小 PWM 地板 `minpwm`（默认 70，日志里实测外轮 70 能持续转）**：方案A降速后的外轮低于此值会被抬回，防止弯道里外轮堵转直接停车。
- **sharp/发卡的内轮反转保持满速 base**：不被降速削弱，否则发卡掉头力度会腰斩、转不过来。

**代价（在 speed=17 下算一算）**：
| 档 | 外轮目标(降速后) | 经 minpwm=70 地板 | 实际效果 |
|---|---|---|---|
| MEDIUM | 108×0.85=91 | 91（>70） | **有效，外轮降到91** |
| SHARP | 108×0.65×0.65≈46 | 抬回 70 | 与旧值(70)相同，**没降下去** |
| HAIRPIN | 108×0.50×0.65≈35 | 抬回 70 | 与旧值(70)相同，**没降下去** |

也就是说：**外轮本来就已被 turn_outer_ratio 压到 ~70(接近死区地板)，方案A在 sharp/发卡上几乎没有再降的空间**，当前只有 MEDIUM 档真正慢下来(91)。要让 sharp/发卡也降，得先确认电机能在更低 PWM 持续转，再把 `minpwm` 调低(如 `minpwm 55`)试——但低于死区就会堵转停车。

**结论**：方案A能压一点 MEDIUM 档的入弯速度，但**受电机死区限制，对 sharp/发卡帮助有限**。"太快冲进弯"这个问题在当前电机上，**根子还是死区/齿轮比(硬件)**——见 `如何判断当前有没有机械延迟.md` 第六、七节。软件能做的有限，别指望方案A单独救。

#### 验证方法
`algo 0` 用默认（85/65/50, minpwm 70）重跑本弯道，比对 `00 A`/`00 B`（LOST）次数是否下降。
- 想让 sharp/发卡也降速：先手动 `go` 试出电机"运动中不失速"的最低 PWM，把 `minpwm` 设到那附近，再调低 `sharpspeed/hairpinspeed`。
- 若车在弯里堵转停：把 `minpwm` 调高。
